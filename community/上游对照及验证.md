# RTX 3070 macOS 驱动 3.0.2 本地整合与上游对照

**2026 年 11 月 21 日。** 该包用于更新已安装 NullMoth 3.0 且固件齐备的 x86_64 macOS 26。安装器检查 RTX 3070 的 PCI 标识 `10de:2488`。桌面实测平台为 RTX 3070 8 GiB、macOS 26.6.2（25G83）、5120 × 2880、160 Hz。源码归档同时保留实验项。复核这些实验时，应以实际装包的二进制清单为准。

| 源码区域 | 变更文件 | 内容 |

| `plugin` | 11 | Metal 合成与提交完成通知、IOSurface 导入复用、纹理上传、主机内存所有权和延迟回收、着色器库及诊断 |

## 安装包中运行的组件

将包内清单的 20 个组件与线上 v3.0 发行包按 SHA-256 逐一比较，6 个二进制发生变化，包括两版 NVAccel、NVRMFB、NVMTLDriver、NVK 和 VideoToolbox 库 `libnvencvt.dylib`。其余 14 个相同。适用于本机 macOS 26 的 19 个组件均与已安装文件逐字节一致。源码归档的 `comparison/shipped-binary-diff.json` 提供对应路径与双方的完整哈希。

| 组件 | 选用的版本 |
|---|---|
| NVRMFB | 本机已经重启加载的显存预备池版本，UUID `860AC4A5-4FAD-3C09-80E4-59F9F287CFA7`。在支持的大 BAR1 上按最近两种尺寸备货，总上限 448 MiB |
| NVAccel | 同一组本地 Frame Sync 修订的 macOS 15 与 26 变体。26 实机加载 UUID 为 `5714A570-CCED-3AAD-BA38-AB0ACE2C82A2`。15 变体只做包内静态检查 |
| NVMTLDriver | 当前 WindowServer 实际加载的本地 Metal 构建，UUID `C2145874-1980-3DAB-A52B-EEF95603569E`。本地诊断构建与上游发布构建的编译选项有差异，因此安装包标记为本机使用 |
| NVK | 与本机一致的着色器显存版 `libvulkan_nouveau.dylib`，SHA-256 前缀 `4e56026f6782` |
| NVRM、NVRMAGDC、音频和视频库 | 按已验证的本地基础包和实装组件清单匹配。NVRM 继续用实机加载版本 `91B2C401-3918-3F5B-9110-6B4AE344BE7E` |
| 配置与工具 | 打包本地表面导入缓存和主机页共享配置。全局 ANGLE Metal 偏好和启用 GPU Boost 各有独立选项，默认仅选驱动；已有的 Boost 启用状态由机器保留 |

源码中另有 NVRM/NVK 单 fence 时间跟踪及 NVK Boost 续期实验。Boost 补丁的挂钩位置、空闲时续期行为与仓库测试的预期有差异。归档保存它们的实际状态。当前 `build/build_nvk.sh` 的补丁链也没有列入单独的 `nvk-shader-vram.patch`。从当前树直接执行该构建命令，不能据此声称能复现包内已测 NVK。安装包采用逐组件校验过的既有产物。

整合包 SHA-256 为 `c222cca0efe23a3df0ce2ffbefde561e7db8f54b5fdb6e22ff382e54da396b91`。已经解包反查载荷、组件哈希、许可文本和三项安装选择。外层 PKG 未使用 Developer ID Installer 签名。已有实机数据来自相同核心组件，本次没有用新封装执行覆盖安装、重启或验证回退。

源码 ZIP 内的 `nvidia-macos-driver/` 是当前本地工作树的完整源码快照，共 1,559 个文件，逐个核对 Git 文件内容和可执行位。`comparison/` 保存净差异、逐文件增删量和版本标识，`packaging/` 保存本地装配脚本及组件清单，`evidence/` 保存对比与实测记录。`companion/performance-viewer/` 保存独立采样工具的源码及构建脚本。装配脚本还依赖有固定哈希的旧版产物和本地目录布局，因此 ZIP 不是独立的一键二进制构建环境。

## 上游组件对测与本地整机实测

**线上 v3.0 的 Metal 插件与本地实装插件。** 已校验上游发布归档 SHA-256 为 `40f0390d0b7cda75637991879b09abb7f8f7e3e5db2e811196963b3a2cacbcad`。测试进程分别加载指定插件，保留相同的本机内核驱动和 Vulkan 库。两个 Metal 队列通过共享事件同步，写入一张 512 × 512 BGRA8 表面并读回核对像素。上游、本地、本地、上游各跑 240 次，两个版本各 **480/480 次通过**。四轮中位耗时依次为 0.424、0.357、0.144、0.142 ms。轮间波动较大，这项对测没有显示稳定的速度优势。上游全套驱动未替换到当前系统做整机对照。

**本地显存池升级前后。** 下表来自同一张 RTX 3070 上两次实际启动，显示器和渲染规格一致。分配测试使用两种尺寸，预热后交替进行四轮，每轮三次。拖窗前后各一轮，应用切换前后各 20 次。

| 指标 | 先前本地驱动 | 本地 3.0.2 |
|---|---:|---:|
| 预热后大缓冲区命中 | 4/12 | 12/12 |
| 分配耗时中位数 | 159.1 ms | 8.7 ms |
| 三轮可见 5K 窗口超过 100 ms 的翻页间隔 | 7 次 | 1 次 |
| 8 秒标题栏拖动，翻页间隔 P95 | 21.0 ms | 16.0 ms |
| 应用切换，前台确认 P95 | 57.6 ms | 29.0 ms |
| 应用切换，请求后首个全局翻页 P95 | 32.1 ms | 40.4 ms |

首次遇到尚未预备的尺寸仍测到 225 ms。新版在三块缓冲区均命中的一轮 5K 测试里也出现了一次至少 141 ms 的翻页间隔。原日志中的约 800 ms 停顿在该复测中没有复现。

## 自动测试与投稿条件

使用相同依赖、干净环境和仓库主机测试入口。**上游 main 为 241 项通过、5 项失败、9 项未运行；本地快照为 256 项通过、8 项失败、10 项未运行。** 两者共有五个失败项，涉及 Python zstd 能力、历史测试对照及其他上游测试条件。本地额外三项分别涉及标签版目录清单、对脏工作区的历史对照假设、实验性 Boost 补丁。目录清单在上游 main 已修正；连接通知测试用真正的修复前版本作负对照后通过。原始测试结果和补充验证保存在源码包的 `evidence/` 中。
